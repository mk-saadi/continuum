## Root cause and bounded profile

`experimental/network_owner.py:limits()` set hard/soft RLIMIT_AS=512 MiB in `_spawn`. `networkExecutionWorker.py:execute()` used that same helper for nsenter → bubblewrap → shell → Node. Bubblewrap inherited this kernel limit; it did not independently select it. RLIMIT_DATA and RLIMIT_RSS were unlimited on the host. RSS rlimits are not used as Linux resident-memory enforcement. The host's own AS limit was unlimited. The reproduced V8 CodeRange failure was virtual reservation failure, not evidence of exhausted physical RAM.

The B2-D Python backend now starts inside an absolute-path `/usr/bin/systemd-run --user --scope` with MemoryMax=1 GiB, MemorySwapMax=0, TasksMax=128 and CPUQuota=200%. This is a disposable user scope, not a host-wide setting. The worker reads its actual unified cgroup placement and requires effective numeric memory/swap/task/CPU limits before creating an owner or executing anything. It enables and verifies memory.oom.group only on that disposable scope. The supported host's systemd 255 does not accept the newer MemoryOOMGroup unit property; writing the delegated scope's kernel control was verified instead. No ancestor controls or host delegation settings are changed.

Only sandbox command launches use a 64 TiB virtual-address-space ceiling. Trusted owner/transport/preview helpers keep their 512 MiB profile. Both retain 60 CPU seconds per process, 256 descriptors and zero core dumps. Standard Node receives no JIT, WebAssembly or heap workaround flags. Physical memory, mapped/file-backed memory charged to the scope, descendants and helper overhead share the hard cgroup budget; all descendants share the task and CPU quota. Two existing application owner slots bound simultaneous managed network scopes to 2 GiB and 256 tasks (outside application/browser overhead). Four commands per owner, existing B1 maximum 30-minute command lifetime, finite foreground timeouts and cancellation remain in force. This adds no process lifecycle registry.

The user manager and delegated cgroup v2 memory/pids/cpu controls are prerequisites for this profile. No systemd user bus, ineffective/missing controllers, or inability to set group OOM fails closed. No unbounded-RSS fallback exists. Python/utilities and systemd remain unqualified packaged prerequisites. Resource validation now requires the absolute systemd-run executable too.

Actual tests read command RLIMIT_AS/CPU/NOFILE/DATA/RSS, verify kernel memory/swap/tasks settings, start standard Node, hit the descriptor ceiling, and allocate a bounded 1.5 GiB inside the 1 GiB scope. Group OOM terminates the worker and helpers; no live captured scope PIDs remain and the B1/network service releases ownership. Deterministic tests reject unlimited, missing and oversized controllers and legacy cgroups.

## Real isolated Vite acceptance

A disposable Vite project copies installed dependencies; no install/download or host-executed Vite substitute is used. The standard `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 43119 --strictPort` runs through the approved native dispatcher, verified filesystem plan, real namespace owner and B1. A separate sandbox command reaches guest localhost. The pipe-only gateway verifies command-port ownership and returns HTTP 200. Real installed Chrome completes the single-use handoff, loads assets/CSS, computes the expected CSS color, executes JavaScript, reloads, connects a same-origin HMR WebSocket and observes an update frame plus changed DOM after a source edit. The test waits for the HMR connection before editing, avoiding a startup race in the original fixture.

Successful run completion preserves server and preview. A later authorized run in the same session/workspace reads status. Stop makes the preview unreachable and leaves both gateway and network registries empty. Distinct sessions/workspaces remain unauthorized; later-run access does not mean cross-session access.

Real B1 tests cover command-port ownership, sibling denial, port reassignment, expiry, permission/rule revocation, session termination/deletion and shutdown. Final real fixtures assert that resolver scratch roots disappear, including abrupt parent death. No pre-existing scratch directories are removed. No unrelated processes are terminated. B2-C independently repeats helper/owner failure, control EOF and parent-death security coverage. Arbitrary malformed protocol fuzzing, sustained throughput/DoS qualification and every possible OS scheduler/port race are not claimed.
